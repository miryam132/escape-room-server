# ארכיטקטורה והחלטות

React שולח HTTP ל־Express. הנתיב מפעיל אימות והרשאות, Controller בודק קלט ומעביר ל־Service. השירות משתמש ב־Prisma מול PostgreSQL. תמונות עוברות דרך השרת אל Supabase Storage. אין פנייה ישירה של React לטבלאות או למפתח השרת.

## הישויות

- User: UUID ראשי, שם, אימייל ייחודי, passwordHash, תפקיד ותאריך יצירה.
- Room: UUID ראשי, שם, תיאור, קטגוריה, קושי, כתובת/מפתח תמונה, revision ותאריכים.
- Hotspot: UUID ראשי, roomId זר, סוג, מיקום, תוכן ושדות חידה. prerequisiteId הוא קשר עצמי אופציונלי.
- GameProgress: UUID ראשי, userId ו־roomId זרים, צירוף ייחודי של שניהם, גרסה, מצב ותאריכים.
- SolvedHotspot: מפתח משולב progressId+hotspotId, שני מפתחות זרים ותאריך פתרון.

הפירוט המדויק והטיפוסים נמצאים ב־prisma/schema.prisma. ה־Migration כולל אינדקס ייחודי לחידת סיום אחת בחדר, מגבלות קואורדינטות, איסור תלות עצמית ו־RLS. חידה אינה יכולה להסתמך על חידה מחדר אחר, ליצור מעגל או להיות תלויה בחידת סיום; אלה נאכפים בשירות.

## שמירת עקביות

כל פעולה המשנה חדר או משחק נועלת את שורת החדר בתוך transaction. גם פתיחת נקודה וקריאת מצב משתמשות בנעילה כדי לא להחזיר מצב מעורב בזמן עריכה. זה פשוט ומתאים לפרויקט קטן, אבל מסדר פעולות באותו חדר בתור קצר; אינו תכנון למשחק המוני בזמן אמת.

שינוי נקודה מוחק התקדמויות ומעלה את revision. לקוח חייב לשלוח revision בתשובה ובאיפוס. כך בקשה ישנה לא תפתור בטעות גרסה חדשה. תלות בחידה אחת נשמרת כנתון; מצבי LOCKED/AVAILABLE/SOLVED מחושבים ואינם נשמרים בנפרד.

## אבטחה

JWT מסוג HS256 עם issuer, audience, תוקף של שעתיים ו־subject שהוא UUID. בכל בקשה נבדק שהמשתמש עדיין קיים ונקרא תפקידו מהמסד. סיסמאות מגובבות ב־bcrypt בעלות 12. Zod דוחה שדות לא מוכרים, לרבות ניסיון להירשם כמנהל. אין Endpoint לשינוי תפקיד.

מידע לשחקן נבנה בשדות נבחרים. תשובות אינן נשלחות; תוכן לאחר פתרון אינו נשלח לפני פתרון; תוכן חידה נעולה אינו נשלח. מזהה השחקן נלקח מה־Token בלבד.

מוגדרים Helmet, CORS מוגבל לכתובות מפורשות, JSON עד 64KB, עד 180 קריאות API לדקה ל־IP, עד 30 ניסיונות אימות ב־15 דקות ועד 10 העלאות בדקה. מגבלות התעבורה נשמרות בזיכרון של תהליך אחד ואינן משותפות לכמה שרתים. ההגדרות מיועדות למופע יחיד ולפרויקט לימודי.

העלאה מחייבת מנהל. מתקבל קובץ אחד עד 5MB; Sharp מפענח, מגביל ל־25 מיליון פיקסלים, מסיר מטא־דאטה בקידוד מחדש, מקטין עד 2400×2400 ושומר WebP בשם אקראי. אין SVG, HTML או GIF. אין שרת קבצים מקומי בפריסה.

RLS מופעל ללא מדיניות של לקוחות; Prisma חייב להתחבר כבעל הטבלאות. שמור את סכמה escape_room מחוץ ל־Exposed schemas. שירות ההתחברות הוא של השרת; לא משתמשים ב־Supabase Auth ולכן לא מערבבים שני מנגנוני התחברות.

## מסירה ותחזוקה

אין שינוי בקוד React הקיים. מדריך החיבור מסביר את שינויי חוזה ה־API. אין פריסה או חשבונות ענן שנוצרו אוטומטית. יידרשו מסד, Bucket, משתני סביבה וחשבון מנהל לפי START-HERE.

ה־Seed אינו מוחק או דורס נתונים קיימים. מיגרציות אינן כוללות סיסמאות. בדיקות פועלות בסכמה מבודדת ושומרות הפרדה מהמסד של המשתמש.
